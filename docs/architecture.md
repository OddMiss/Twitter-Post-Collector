# Architecture

## Overview

X-Agent is a local-first collector. The Edge extension reads posts from the X tab that the user is already viewing, and a Python service on the same machine validates, deduplicates, stores, summarizes, and archives them.

```text
Logged-in X tab
      │  DOM + visible media markers
      ▼
Edge extension (content.js)
      │  localhost HTTP + random token
      ▼
Python collector (x_collector_server.py)
      ├─ incremental JSONL/Markdown writer
      ├─ SQLite permanent history index
      ├─ local or optional OpenAI summarizer
      └─ Beijing-time daily archiver
```

## Components

| Component | Responsibility |
| --- | --- |
| `edge-extension/content.js` | Expands `Show more`, extracts visible posts, adds `[视频]`, `[图片]`, `[文章]`, scrolls, and performs in-session deduplication. |
| `edge-extension/background.js` | Keeps the localhost connection and background wake-up/scroll behavior alive while the popup is closed. |
| `edge-extension/popup.*` | Stores the local token and scroll preferences and starts/stops a collection round. |
| `x_collector_server.py` | Local HTTP API, input validation, permanent deduplication, batch lifecycle, and summary orchestration. |
| `x_digest.py` | Shared post model, incremental writers, local summary, optional OpenAI summary, and legacy Playwright collector. |
| `organize_posts_by_date.py` | Incrementally normalizes timestamps to Asia/Shanghai and writes sorted daily JSON files. |
| `test_*.py` | Offline unit and integration tests; no X login or network access is required. |

## Data flow and persistence

1. The extension extracts a post only from the active X/Twitter tab. It does not read cookies or call X's private API.
2. Posts are sent in small HTTP batches to `127.0.0.1` with the token generated by the Python service.
3. The server validates the URL, ID, text size, and field lengths before processing.
4. The SQLite index checks both the post ID and a normalized `author + body` fingerprint. This makes deduplication survive restarts and URL/ID changes.
5. Accepted posts are written immediately to `output/browsed-*.jsonl` and `output/browsed-*.md`. A completed round also writes `posts-*.json` and `summary-*.md`.
6. Posts with a parseable timezone-aware timestamp are incrementally copied to `output-by-date/YYYYMMDD.json` in Beijing time.

All generated data is intentionally ignored by Git. A public repository should contain code and documentation, not collected posts, account-specific tokens, cookies, or SQLite history.

## Trust boundaries

- The extension has access to the X pages declared in `manifest.json` and the localhost collector endpoint.
- The Python service binds only to `127.0.0.1` by default.
- The token is an installation-local shared secret, not an account credential.
- OpenAI summarization is opt-in through `.env`; local mode does not send post text to an external service.
- Treat collected text as untrusted input. The server rejects non-X URLs and oversized fields, but summaries should still be reviewed before publication.

## Extension release checklist

1. Bump `edge-extension/manifest.json` version.
2. Run `node --check edge-extension/content.js` and `node --check edge-extension/popup.js`.
3. Run the Python test suite.
4. Load the unpacked extension in a clean Edge profile and test start, background collection, manual stop, and summary generation.
5. Verify that `git status` shows no `.env`, `.collector-token`, `output/`, `output-by-date/`, browser profile, or SQLite files.
